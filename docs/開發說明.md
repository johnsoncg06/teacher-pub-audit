# 開發說明

## 目錄

| 路徑 | 說明 |
|---|---|
| `app.html` | **建置產物**（單一 HTML，含全部程式與資料）。PyInstaller 打包時使用，不要手動編輯 |
| `src/app.html` | 介面與流程的原始碼（含 `<!--CORE-->` 等佔位符） |
| `src/core.js` | 核心邏輯：讀檔、姓名變體、檢索式、比對、期刊品質、彙總（無外部套件） |
| `src/jcr_data.js` | 內建期刊品質資料，由 `tools/build_jcr_data.py` 產生 |
| `src/i18n.js`、`src/i18n_dict_*.py` | 多語系：執行時翻譯層與詞典（繁中為原文，鍵即中文原句） |
| `src/build.py` | 合併成根目錄的 `app.html` |
| `main.py` | 桌面殼（pywebview）、API Key 鑰匙圈、WoS API 請求 |
| `tests/` | 測試（全部使用虛構的範例資料，不含任何真實人員或 WoS 資料） |
| `tools/` | 維護工具（更新 JCR 資料） |

## 修改流程

```bash
# 1. 改 src/ 內的檔案
python3 src/build.py          # 2. 重新產生 app.html
npm install && npm test       # 3. 測試（首次需 npx playwright install chromium）
# 4. src/ 與 app.html 一起提交、推送；CI 會再檢查一致性並編譯發布
```

CI（`.github/workflows/test.yml`）會重新建置並比對 `app.html`，不一致就失敗，避免忘記重建。

## 新增或修改介面文字

介面文字以繁體中文為原文。改了中文句子，其他語言的詞典鍵就對不上，會悄悄退回中文：

1. 在 `src/i18n_dict_d.py`（或對應檔）新增或修改 `(繁中, English, 日本語, 한국어, Español)`，變數用 `{0}`、`{1}`，各語言的變數集合要和繁中相同。
2. 不要讓翻譯層碰使用者資料（姓名、系所、備註等），在元素上加 `translate="no"`。
3. `npm test` 內的 `check_dict.py` 檢查詞典格式，`i18n_coverage.js` 會逐步檢視所有畫面，列出漏譯的文字。

**譯文未經母語人士審閱**，介面與報表在非繁中語言時會顯示免責聲明；若要正式對外使用其他語言，請先請母語人士校對詞典。

## 範例資料

App 步驟 1 的「載入範例資料」由 `src/app.html` 的 `buildSample()` 產生：8 位虛構教師、36 篇虛構論文，涵蓋「確定掛本校／疑似漏掛／同名他人／無法判定」四種情況。測試以它的固定數字（採計 31 篇、Q1 17、Q1+Q2 38）作為回歸基準；改動比對或採計規則時，這些數字會變，需同步更新 `tests/e2e_sample.js` 並說明原因。
